# summary

I've identified and fixed the issue with `zinfo-web` not producing output.

## Diagnosis

After investigating, the problem stemmed from two issues in `src/zinfo/ui/fh_ui.py`:

1. **Non-blocking server startup**: The `run()` function called FastHTML's `serve()`, which returned immediately without actually starting the web server (despite printing success messages).

2. **Missing CLI interface**: The `run()` function wasn't a Click command, so `zinfo-web --help` produced no output instead of showing usage information.

## Validation

I added logging to confirm the server wasn't starting properly with `serve()`, then switched to `uvicorn.run(app, host=host, port=port)` which correctly blocks and starts the server. I also converted `run()` to a Click command with `--host` and `--port` options.

## Fix Applied

- Modified `run()` to be a `@click.command()` with options for host and port
- Replaced `serve()` with direct `uvicorn.run()` call
- Added Click import

Now `zinfo-web --help` shows proper usage, and `zinfo-web` starts the server on http://0.0.0.0:5001 as expected.

The web UI is now functional and can be accessed in a browser.
